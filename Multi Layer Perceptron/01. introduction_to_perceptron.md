## The Smallest Brick

Until now, Deep Learning has probably felt like a story told from a distance: the history, the big ideas, the reasons it matters. Now you step inside and look at the machinery.

The first piece of machinery is the **Perceptron**, the fundamental building block of an Artificial Neural Network.

You might wonder: *why start with one neuron when real networks have thousands?*

Because a network is just many Perceptrons wired together. If you understand how **one** is built, how it sees data, and how it learns, then a Multi-Layer Perceptron (MLP) stops being magic and becomes *"the same thing, repeated."*

So the road ahead looks like this:

1. What a Perceptron **is**
2. Its **mathematical** structure
3. Its **geometric** intuition
4. How it looks in **code**
5. How it is **trained** (the next chapter's job)
6. Its **limits**, which is exactly why MLPs exist

A Perceptron is a **supervised** machine learning algorithm. It learns from labelled data, just like Linear Regression, Logistic Regression and SVM do. You can describe it three ways, and all three are true:

- 🧩 an **algorithm**
- 📐 a **mathematical model**
- ƒ a **mathematical function**

Let's open it up.

---

## Anatomy of a Perceptron

Picture a small machine with a few parts:

```
   x₁ ──(w₁)──┐
               ├──▶ [ Σ  weighted sum + bias ] ──▶ [ Activation ] ──▶ Output
   x₂ ──(w₂)──┤
               │
   1  ──(b )──┘
```

Six parts, one job each:

| Part | What it is |
|---|---|
| **Inputs** | The features you feed in |
| **Weights** | One number per input, deciding how much that input matters |
| **Bias** | An extra number added to the sum |
| **Summation** | Combines everything into one value |
| **Activation function** | Turns that value into the final output |
| **Output** | The prediction |

### The running example

Imagine a dataset of 1,000 students:

| IQ | CGPA | Placement |
|---|---|---|
| 78 | 7.8 | 1 |
| 69 | 5.1 | 0 |
| 100 | 8.5 | 1 |
| 85 | 6.2 | 1 |
| 65 | 4.5 | 0 |

`Placement = 1` means the student got placed; `0` means they didn't. The goal: **learn from these rows, then predict placement for a brand-new student from just their IQ and CGPA.**

So the inputs are:

- $x_1$ = IQ
- $x_2$ = CGPA

### Weights: the importance dials

Every input gets its own weight:

- $w_1$ goes with IQ
- $w_2$ goes with CGPA

The Perceptron multiplies each input by its weight. So $w_1x_1$ is *IQ's contribution* and $w_2x_2$ is *CGPA's contribution*.

### Bias: the constant nudge

The bias $b$ is added on top of the weighted inputs. A neat way to picture it is as one more input that is always fixed at `1`, with its own weight $b$:

$$b \times 1 = b$$

Its deeper role shows up in the geometry section. Hold that thought. 🔖

### Summation: one number from many

Put it together:

$$\boxed{z = w_1x_1 + w_2x_2 + b}$$

This is a **dot product** of the inputs with their weights, plus the bias. Let's plug in real numbers.

Take $x_1 = 78$, $x_2 = 7.8$, and suppose $w_1 = 1$, $w_2 = 2$, $b = 3$:

$$z = (78 \times 1) + (7.8 \times 2) + 3$$

$$z = 78 + 15.6 + 3$$

$$\boxed{z = 96.6}$$

That number is the **weighted sum before activation**. It is not a prediction yet, just a raw score.

### Activation: from a raw score to a decision

The raw score $z$ can be anything: 96.6, -4, 0.3. We need a *decision*. The **activation function** squeezes $z$ into a fixed output range, such as $\{0, 1\}$ or $\{-1, 1\}$.

This Perceptron uses the **Step Function**:

$$f(z)=\begin{cases}1 & z \ge 0\\ 0 & z < 0\end{cases}$$

*Non-negative score → 1. Negative score → 0.*

(There are other activation functions, such as **ReLU**, but a Perceptron's classic form uses the step.)

For our student, $z = 96.6 \ge 0$, so the output is **1**: *placed*.

The whole machine, in one line:

$$\boxed{\text{Inputs} \rightarrow \text{Weights} \rightarrow \text{Summation} \rightarrow \text{Activation} \rightarrow \text{Output}}$$

## Training vs Prediction

You have the machine. But where do $w_1$, $w_2$ and $b$ come from? 🤔

That question splits the Perceptron's life into **two stages**.

### Stage 1: Training 🏋️

The Perceptron looks at existing student records, each with a known placement result. Its entire goal is to **find good values of $w_1$, $w_2$ and $b$**. These three numbers are what the model *learns*. Everything else (the sum, the step function) is fixed machinery.

*How* the weights get adjusted is the Perceptron learning rule, which is the next chapter's story. For now, just hold the goal: **training = finding the weights and bias.**

### Stage 2: Prediction 🔮

Once training is done, the weights are frozen and used on new data.

Suppose training gave $w_1 = 1$, $w_2 = 2$, $b = 3$. A new student arrives with **IQ = 100** and **CGPA = 5.1**.

$$z = w_1x_1 + w_2x_2 + b$$

$$z = (1 \times 100) + (2 \times 5.1) + 3$$

$$z = 100 + 10.2 + 3$$

$$\boxed{z = 113.2}$$

Since $z \ge 0$, the step function outputs **1**. Prediction: *placed*.

> 💡 **A small arithmetic trap:** a transcript of this example can easily show `1132` instead of `113.2`. Check it yourself: $100 + 10.2 + 3 = 113.2$. The decimal point matters, so always recompute.

The distinction to keep forever:

- **Training** *calculates* the weights and bias.
- **Prediction** *uses* them.

## More Than Two Inputs

*"What if I have more features than just IQ and CGPA?"*

Nothing breaks. Add a third feature, say 12th-grade marks as $x_3$, and the machine simply grows one more input and one more weight:

$$\boxed{z = w_1x_1 + w_2x_2 + w_3x_3 + b}$$

In general, with $n$ features:

$$y = f(w_1x_1 + w_2x_2 + \cdots + w_nx_n + b)$$

**One input = one connection = one weight.** The structure never changes; it only gets wider.

## Biological Neuron vs Artificial Perceptron

Deep Learning is *inspired* by the nervous system, so it's fair to ask how a Perceptron compares with the real thing.

A biological neuron has three parts worth knowing:

- 🌿 **Dendrites**: branch-like structures that *receive* incoming signals
- 🔬 **Nucleus / cell body**: where the neuron processes what it received
- ⚡ **Axon**: the cable that carries the *output* signal onward

Line them up:

| Biological neuron | Artificial Perceptron |
|---|---|
| Dendrites receive signals | Inputs are received |
| Connections carry signals, with varying strength | Weights scale each input |
| Processing inside the cell | Weighted summation + activation |
| Axon carries the output | The output value |

The resemblance is real, but it is **inspiration, not duplication**. The two differ in three important ways.

**1. Complexity.** A biological neuron connects to many other neurons in an extremely rich way. A Perceptron is a deliberately simplified mathematical model you can write on one line.

**2. Internal processing.** A biological neuron works through electrochemical processes. A Perceptron performs exactly two simple operations: a weighted sum and a step.

**3. Neuroplasticity.** This one is subtle. Biological connections can **strengthen, weaken, disappear, or newly form** as you learn, which is why practising a skill changes your brain. A Perceptron's *wiring* is fixed: the inputs it connects to never change. Only the *strengths* (the weights) get tuned during training.

> *"The Perceptron is weakly inspired by the biological neuron. It is not a copy of how a neuron works."*

## What the Weights Tell You

Suppose training produced $w_1 = 2$ (IQ) and $w_2 = 4$ (CGPA).

Reading these as *connection strengths*: CGPA's weight is twice IQ's. So in this example, a unit change in CGPA moves the score twice as much as a unit change in IQ. This leads to a useful idea:

$$\boxed{\text{Weights carry information about feature importance}}$$

A bigger weight (in magnitude) means that input pushes the score harder. The weights aren't just numbers the model needs; they're a **peek into what the model cares about**.

> ⚠️ **The honest caveat:** this reading is only fair when the features are on **comparable scales**. IQ lives around 60 to 140, CGPA around 0 to 10. A weight of 4 on a feature that ranges over 10 units and a weight of 2 on one that ranges over 80 units are *not* directly comparable. That's one more reason feature scaling matters. Treat weight-as-importance as a first intuition, not a final verdict.

## The Geometry: A Perceptron Is a Line

This is the heart of the chapter. 📐

### Step 1: Put the data on a graph

Take the student data and plot it:

- X-axis = IQ
- Y-axis = CGPA

Every student becomes **one point**. Colour the points by outcome:

- 🟢 green = placed
- 🔴 red = not placed

Students with high IQ and high CGPA cluster in the green zone; low values cluster in the red zone. The Perceptron's job is to **separate the two colours**.

### Step 2: Look at the equation differently

We know the score is:

$$z = w_1x_1 + w_2x_2 + b$$

Rename the symbols: $w_1 \to A$, $w_2 \to B$, $b \to C$, and the axes $x_1 \to x$, $x_2 \to y$. Now:

$$Ax + By + C$$

Set it to zero and you get something you've seen since school:

$$\boxed{Ax + By + C = 0}$$

**That is the equation of a straight line.** So with two inputs, the Perceptron's decision boundary *is a straight line*.

### Step 3: What the line does to the graph

The line splits the plane into two regions:

| Region | Condition | Prediction |
|---|---|---|
| One side of the line | $Ax + By + C > 0$ | $y = 1$ (placed) |
| The other side | $Ax + By + C < 0$ | $y = 0$ (not placed) |

(Points exactly *on* the line give $z = 0$; with the "$\ge 0$" step convention they get class 1.)

```
 CGPA
  ▲
  │  🔴 🔴        ╲
  │    🔴     🔴   ╲     🟢  🟢
  │  🔴    🔴       ╲  🟢    🟢
  │     🔴           ╲   🟢
  │                    ╲
  └──────────────────────╲────▶ IQ
      z < 0 (class 0)      z > 0 (class 1)
```

To classify a new student, the Perceptron places them on the graph and asks one question: **which side of the line are they on?**

$$\boxed{\text{Perceptron} = \text{Decision Boundary} + \text{Two Decision Regions}}$$

### A tiny worked example

Say a model has $w_1 = 1$, $w_2 = 1$, $b = -10$. Its boundary is:

$$x_1 + x_2 - 10 = 0 \quad\Rightarrow\quad x_2 = -x_1 + 10$$

(In general, $Ax + By + C = 0$ rearranges to $y = -\frac{A}{B}x - \frac{C}{B}$: slope $-\frac{A}{B}$, intercept $-\frac{C}{B}$.)

Test three students, using (CGPA, Resume Score):

| Point | $z = x_1 + x_2 - 10$ | Side | Output |
|---|---|---|---|
| (8, 7) | $8 + 7 - 10 = 5$ | positive | **1** |
| (3, 4) | $3 + 4 - 10 = -3$ | negative | **0** |
| (5, 5) | $5 + 5 - 10 = 0$ | on the line | **1** |

### And what does the bias do?

Look at $Ax + By + C = 0$ once more. If $C = 0$, the point $(0, 0)$ satisfies it: $A\cdot 0 + B\cdot 0 + 0 = 0$. So **with no bias, the line is forced through the origin.** The bias $b$ is what lets the line *slide away from the origin* to wherever the data actually needs it. Without it, the Perceptron could only draw lines through $(0,0)$, which is a harsh restriction.

## Line, Plane, Hyperplane

*"Fine for two features. But what about three? Or a hundred?"*

The idea scales cleanly:

| Number of inputs | Equation | Decision boundary |
|---|---|---|
| 2 | $w_1x_1 + w_2x_2 + b = 0$ | **Line** (in 2D) |
| 3 | $w_1x_1 + w_2x_2 + w_3x_3 + b = 0$ | **Plane** (in 3D) |
| 4 or more | $w_1x_1 + \cdots + w_nx_n + b = 0$ | **Hyperplane** |

For three inputs, imagine a flat sheet slicing a room in two: class 0 on one side, class 1 on the other. You can't draw a hyperplane in 100 dimensions, but the logic is identical. *One flat boundary, two sides.* That's why the Perceptron is a **binary classifier**.

## The Wall a Single Perceptron Hits

If a Perceptron can only draw **one straight boundary**, what kinds of data can it handle? There are three cases.

**1. Linearly separable.** One straight line cleanly splits the classes.

```
   🔴 🔴 🔴 │ 🟢 🟢 🟢
   🔴 🔴    │    🟢 🟢        ✅ Perfect for a Perceptron
   🔴 🔴 🔴 │ 🟢 🟢
```

**2. Approximately linearly separable.** Most points fall on the correct side, with a few mixed in. A line still does a decent job, though accuracy drops.

**3. Non-linearly separable.** No single straight line can separate the classes.

```
        🟢 🟢 🟢 🟢
      🟢  🔴 🔴 🔴  🟢
      🟢  🔴 🔴 🔴  🟢        ❌ Red is surrounded by green.
      🟢  🔴 🔴 🔴  🟢           No straight line can split them.
        🟢 🟢 🟢 🟢
```

Here a single Perceptron struggles badly, because its boundary is *always* linear.

$$\boxed{\text{A single Perceptron cannot effectively classify complex non-linear patterns.}}$$

This limitation is historically important. It's the reason people started stacking Perceptrons into **Multi-Layer Perceptrons**, a story for later chapters.

## "Wait... this is just Logistic Regression"

Maybe somewhere in the middle of all this you thought:

> **"my god, this is just logistic regression !!!"** 😂

You're not wrong to feel that. You spotted something real.

**What's identical:**

- Both compute the same weighted sum, $z = w_1x_1 + w_2x_2 + b$.
- Both produce a **linear decision boundary**, $w_1x_1 + w_2x_2 + b = 0$.
- Both fail on non-linearly-separable data.

**What differs** is *what happens to $z$* and *how the weights are learned*:

| | Perceptron | Logistic Regression |
|---|---|---|
| Weighted sum | ✅ | ✅ |
| Activation | **Step** function | **Sigmoid** function |
| Output | Hard class, 0 or 1 | Probability between 0 and 1 |
| Decision boundary | Linear | Linear |
| Training objective | Perceptron learning rule | Log loss minimisation |

### Step vs Sigmoid, with numbers

The Perceptron says:

$$\hat y=\begin{cases}1 & z\ge 0\\0 & z<0\end{cases}$$

Logistic Regression says:

$$\boxed{P(y=1)=\frac{1}{1+e^{-z}}}$$

Compare on a few scores:

| $z$ | Step output | Sigmoid output |
|---|---|---|
| $0.8$ | 1 | $\frac{1}{1+e^{-0.8}} = \frac{1}{1+0.449} \approx 0.69$ |
| $-1.4$ | 0 | $\frac{1}{1+e^{1.4}} = \frac{1}{1+4.055} \approx 0.20$ |
| $96.6$ | 1 | $\approx 1.00$ |

The step function only says *"placed."* The sigmoid says *"about 69% likely to be placed."* The extra information is the probability.

### Why the boundaries still match

Logistic Regression usually classifies with a threshold of 0.5. When is the sigmoid exactly 0.5?

$$\frac{1}{1+e^{-z}} = 0.5 \;\Rightarrow\; 1 + e^{-z} = 2 \;\Rightarrow\; e^{-z} = 1 \;\Rightarrow\; z = 0$$

And since the sigmoid only ever increases with $z$, it is above 0.5 exactly when $z > 0$. So Logistic Regression's boundary is also $z = 0$, the *same line*.

### The family resemblance

A **linear SVM** also draws a linear boundary. So Perceptron, Logistic Regression and linear SVM share one geometric foundation: *a flat boundary through feature space.* What distinguishes them is the **objective they optimise**, not the shape of the boundary.

> 🧠 So yes, "it's just logistic regression" is *almost* right. A better sentence: **the Perceptron is Logistic Regression's older, harder-edged sibling**, with a step instead of a sigmoid.

## Seeing It in Code

Time to watch the maths turn into Python. Scikit-learn already ships a Perceptron, so there's no need to hand-code the algorithm here.

### The data

A small dataset of 100 students with two features and a target:

| CGPA | Resume Score | Placement |
|---|---|---|
| 7.8 | 8.5 | 1 |
| 5.2 | 4.1 | 0 |
| 8.9 | 9.2 | 1 |
| 6.1 | 5.4 | 0 |

Both features range from 0 to 10; `Placement` is 0 or 1. (A different pair of features from the earlier IQ and CGPA example, but the same idea.)

### Step 1: Look before you model

Plot CGPA on the X-axis and Resume Score on the Y-axis, coloured by placement. If the two colours sit roughly on opposite sides of an imaginary line, the data is **approximately linearly separable**, which makes it a fair test for a Perceptron.

### Step 2: Import, split into inputs and target, create, train

```python
from sklearn.linear_model import Perceptron

X = df[['cgpa', 'resume_score']]   # inputs
y = df['placement']                # target

p = Perceptron()
p.fit(X, y)                        # training: learns w1, w2, b
```

`fit()` is **Stage 1: Training**. It finds the weights and bias.

### Step 3: Read what it learned

```python
p.coef_        # the weights  -> [w1, w2]
p.intercept_   # the bias     -> b
```

In the lesson this was run on, the values came out on the order of:

$$w_1 \approx 40,\qquad w_2 \approx -36,\qquad b \approx -25$$

(Exact numbers will differ with your data and settings; treat these as illustrative.) Notice the **negative** weight on Resume Score. Read literally, a higher resume score would *push toward "not placed"*, which is hard to justify if resumes genuinely help. It's a hint that this untuned fit is rough.

### Step 4: Draw the boundary

```python
from mlxtend.plotting import plot_decision_regions
plot_decision_regions(X.values, y.values, clf=p, legend=2)
```

This shades the plane into the two decision regions and draws the boundary the Perceptron found: the geometry from earlier, now for real.

The accuracy here isn't impressive. The model wasn't tuned and the dataset is small. But that was never the point. The point was to see that **weights → line → two regions** isn't just theory; it's what the library actually does.

## Sanity Check

Before moving on, make sure these hold:

- [ ] **Training** finds $w_1, w_2, b$. **Prediction** reuses them on new data. Never mix the two up.
- [ ] $z = w_1x_1 + w_2x_2 + b$ is a *raw score*; the step function turns it into 0 or 1.
- [ ] $100 + 10.2 + 3 = 113.2$, not 1132.
- [ ] $Ax + By + C = 0$ is the boundary; the sign of $Ax + By + C$ says which side you're on.
- [ ] No bias ($C = 0$) forces the boundary through the origin.
- [ ] 2 inputs → line, 3 → plane, 4+ → hyperplane.
- [ ] Weights hint at feature importance, but only fairly when features share a scale.
- [ ] One Perceptron ⇒ one flat boundary ⇒ it cannot separate non-linear patterns.
- [ ] Perceptron vs Logistic Regression: same $z$, same linear boundary, but step vs sigmoid and different training objectives.

## ML Bridge

Where does this single neuron show up later?

- **Neural networks:** every neuron in a layer computes exactly $z = \mathbf{w}\cdot\mathbf{x} + b$ and then applies an activation function. A layer is many Perceptron-like units side by side; a network is layers stacked.
- **Activation functions:** the step function is the simplest choice. Swap it for sigmoid, tanh or ReLU and you get the neurons that modern networks actually use. The weighted sum stays the same; only the "squeezer" changes.
- **Non-linearity:** the wall a single Perceptron hits is solved by stacking layers with non-linear activations. That is the reason MLPs exist.
- **Training:** "find weights and bias that fit labelled data" is the same goal in a Perceptron, in Logistic Regression, and in a billion-parameter network. Only the machinery for adjusting weights scales up.

## Deepest Realization

🌀 **A Perceptron doesn't "think"; it *measures which side of a line you're on*.**

All the apparent intelligence comes from one thing: *where the line is placed*. Training is just the search for the right position and tilt of that line. And a Multi-Layer Perceptron? It is what you get when one line isn't enough, so you let many lines combine into curves and shapes.

> **"A Perceptron is a weighted vote followed by a hard yes-or-no: it draws one straight line through your data and tells you which side you're standing on. Everything deeper in Deep Learning begins by asking what to do when one line isn't enough."**
